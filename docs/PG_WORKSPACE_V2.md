# PG 업무 화면·개인 초안 v2

2026-11-01 확정 범위. 요청 테이블 → 선택한 요청 미리보기 → 넓은 견적 작업 → 제출 결과 흐름을 사용한다. 설계는 코드 구조에 근거하며 실제 사용자 개선 효과를 측정한 결과는 아니다.

## 저장·공개 계약

- `quote_terms._v=2`가 가입비·보증보험·결제수단별 조건의 기준이다. `unset / confirmed / negotiable / not_applicable` 중 `confirmed`에만 숫자가 있다. 숫자 맵은 확정 수수료만 투영하고 미확정 비용 열은 NULL이다. 과거 `_v=1`의 0은 숫자 0으로 읽고 의미를 백필하지 않는다. 알 수 없거나 손상된 새 문서는 미입력으로 읽는다.
- 정산주기·양수 정산한도와 최소 한 칸의 확정 수수료가 필요하다. 가입비·보증보험은 상태를 반드시 선택한다. 나머지 미입력 수수료도 검토·비교에 표시하고 최저가·개선율에서 제외한다. 수수료는 부가세 별도, 가상계좌는 원/건, 가입비는 원·최초 1회다. 보증보험은 `보증보험 금액(원)`으로만 표기하고 기간·보험료율·금액의 유불리를 추정하지 않는다.
- `bid_drafts`는 사용자·PG workspace·요청·최초/수정 요청 ID별로 유일하다. 액션마다 현재 세션·승인·workspace와 초안 소유자를 확인하고 요청 접근권도 재검증한다. 동료·구매사·운영자 견적 조회에 초안 내용을 전달하지 않는다. 초안 저장은 외부 알림을 만들지 않는다.
- 저장은 `expectedRevision`의 낙관적 잠금을 쓴다. RFP 행 잠금 → 초안 잠금 순서를 제출·저장이 공유한다. 제출은 같은 트랜잭션에서 현재 접수 기간·수정 요청 ID/마감/기준 견적·revision·ready PDF 소유자를 재검증하고 견적·첨부·초안 소비·알림 outbox를 저장한다. 같은 초안 revision의 재시도는 원래 견적 ID를 반환한다.
- 초안은 명시적 삭제·제출 전까지 유지한다. 기한 후 저장·제출은 거부하고 읽기 전용으로 복구한다. 계정의 soft delete와 hard delete 모두 서버 초안을 정리한다. 제출 영수증은 정상 재시도를 위해 소비된 초안에 보관한다.
- 브라우저 복구 키도 사용자·workspace·요청·회차로 구분한다. 입력 즉시 로컬 복구본, 800ms 후 서버 저장을 시도한다. 미완료 PDF는 IndexedDB, 업로드 완료 PDF는 첨부 ID를 사용한다. 파일 저장 실패는 재선택 안내를 표시한다. 충돌은 현재 입력을 보존한 채 저장을 멈추고 사용자가 두 내용을 확인한 후 선택한다. 현재본 저장도 최신 revision을 다시 확인한다.
- 링크·작성창 닫기·이전/다음·새로고침은 미저장 확인을 제공한다. 지원 브라우저에서는 Navigation API로 뒤로/앞으로 이동도 취소할 수 있다. 복구본은 클라이언트 저장 공간이므로 브라우저 삭제·장애를 계정 저장으로 표시하지 않는다. 이전 브라우저 초안은 명시적으로 가져오고 과거 0원을 재확인한다.
- 목록에는 허용된 연간 거래액·접수 시각·본인 초안 존재 여부만 더 투영한다. `OpportunityListing`, 경쟁 PG 정보, `PG_STRIP`, 선정 전 연락처, 노온 합의서 공개 경계는 유지한다.

## 반영 순서

1. DB 백업 후 앱 배포 전에 `scripts/migrations/20261101-pg-workspace-v2.sql`을 대상 DB에 적용한다. 비용 열의 NULL 허용·기본값 제거와 `bid_drafts`·인덱스·FK를 확인한다. 기존 견적의 금액/조건을 백필하지 않는다.
2. 본 서비스와 **별도 admin-supporter-b 콘솔**의 v2 읽기 코드를 배포한다. `PG_QUOTE_V2_WRITE_ENABLED`는 미설정/false로 둔다. 이 상태에서도 초안 저장은 가능하며 새 작성기의 발송은 비활성이다.
3. 스테이징에서 0/미입력/협의 필요/해당 없음의 구매사·PG·운영자 표시, 초안 충돌, 첨부 검증, 중복 제출, 마감 시점 거부를 확인한다. 계정·workspace 변경 후 이전 화면의 저장도 거부되어야 한다.
4. 두 앱이 모두 새 문서를 읽는 것을 확인한 뒤 본 서비스 런타임에 `PG_QUOTE_V2_WRITE_ENABLED=true`를 설정하고 재시작한다. DDL 승인 receipt와 구체적인 배포 명령은 [스테이징](STAGING.md#db-변경-선행-절차)·[Lightsail](DEPLOY_LIGHTSAIL.md)을 따른다.
5. 활성화 후 저장 실패(`bid_draft.save_failed`)·revision 충돌(`bid_draft.revision_conflict`)·제출 실패(`bid_draft.submit_failed` + 오류 코드)의 빈도를 확인한다. 메모·요율·첨부명·회사명·개인 식별자를 운영 지표에 기록하지 않는다.

장애 시 v2 쓰기 플래그를 끈 뒤 새 읽기 코드를 유지한다. v2 행이 생성된 이후 v2를 읽지 못하거나 NULL을 0으로 해석하는 구버전으로 롤백하지 않는다. DDL을 앱 롤백에 맞춰 되돌리지 않는다. 이번 작업 자체는 운영 DDL·배포·플래그 활성화를 실행하지 않는다.

## 이번 변경의 로컬 검증 (2026-11-01)

- 본 서비스 관련 단위·컴포넌트·서비스·DB 테스트 1,333개 통과. 이후 추가한 이전 초안 원본 보존 2개를 포함한 해당 파일 36개도 통과했다. 첨부 업로드의 현재 사용자/workspace 전달 보강 후 작성기 관련 39개를 다시 통과했다.
- 운영자 콘솔의 v2 조회·조건 표 테스트 22개 통과. 두 저장소의 변경 파일 ESLint와 TypeScript 검사, 본 서비스 Next.js 타입 생성 통과.
- Chromium 시나리오 7개 통과: 205건 목록의 URL·페이지·선택 열람·키보드 복귀·1280/1440/390px 패널, 다른 브라우저 초안 복원·충돌·오프라인·이탈 보호·마감 복구, 제출 응답 유실 복구, 실패 PDF의 IndexedDB 복구, 세 화면 폭의 작성·새로고침·제출. 서버에 견적이 한 번 저장되고 미확정 비용은 NULL, 명시적 0은 0으로 기록되는 것을 확인했다.
- PGlite의 기존 스키마에서 마이그레이션을 적용해 과거 0 보존·NULL 기본값·초안 유일성·계정 삭제 cascade·재실행 보존을 확인했다. 격리된 PostgreSQL 테스트 DB(5433)에서도 DDL을 두 번 적용했다.
- 운영 DB·배포·쓰기 플래그 활성화는 실행하지 않았다. 실제 R2 바이트 업로드는 테스트 저장소 설정이 없어 검증하지 않았고, 첨부 소유권/ready 검증·원자 연결 실패·브라우저 원본 복구는 로컬 테스트로 확인했다.
