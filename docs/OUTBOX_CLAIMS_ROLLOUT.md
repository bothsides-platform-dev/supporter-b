# 이메일 Outbox 선점 전환

일반 이메일·상대방 채팅·팀 채팅은 같은 DB 선점 규칙을 사용한다. repository는 선점·갱신·결과 저장을 담당하고 `lib/server/outbox/` 실행기가 전송·백오프를 처리한다. 읽음·프레즌스와 다이제스트 본문은 발송 시점에 각 처리기가 다시 판단한다. 폐지된 `signing.awaiting_template` 메일은 계속 제외한다.

## 저장 계약

- `scheduled_at`은 발송 또는 재시도 예약 시각이다. 선점 때문에 바꾸지 않는다.
- `claim_token`과 `claim_expires_at`은 함께 NULL이거나 함께 값이 있어야 한다. `outbox_claim_pair_check`가 이를 강제한다.
- due 행을 트랜잭션의 `FOR UPDATE SKIP LOCKED`로 읽어 선점한다. 네트워크 호출 동안 DB 행 잠금을 유지하지 않는다.
- 실행기는 네트워크 배치 직전에 소유권을 갱신한다. 성공·취소·실패는 해당 선점 토큰의 결과만 반영한다. 다른 작업자가 다시 선점한 행에는 이전 작업의 늦은 응답을 적용하지 않는다.
- 선점은 5분이며 각 전송 청크 직전에 다시 5분으로 연장한다. 만료만으로 시도 횟수를 늘리지 않고, 만료된 작업의 결과는 성공·실패 집계에도 반영하지 않는다.
- 외부 이메일 서비스와 DB는 하나의 트랜잭션이 아니다. 발송 후 결과 기록 전에 중단되는 경우까지 정확히 한 번 전달을 보장하지 않는다. 기존 공급자 멱등 키와 재시도 정책을 유지한다.

## 배포 순서

이 문서는 절차를 기록하며 운영 DB 적용이나 배포 완료를 뜻하지 않는다.

1. 적용 커밋과 SQL 해시를 기록하고 기존 절차대로 DB 백업을 확보한다.
2. `scripts/migrations/20261022-outbox-claims.sql`을 새 앱 시작 전에 적용한다. nullable 컬럼과 CHECK만 추가하며 기존 행·예약 시각은 보존한다. SQL은 재실행할 수 있고 잠금 획득은 3초, 각 SQL 문장은 30초 제한이다. 실패하면 새 앱을 시작하지 않는다.
3. Outbox cron을 일시 중지한다. **`flock`만으로 구·신 앱의 혼재를 막을 수 없다.** 구 앱은 새 claim 컬럼을 읽지 않으며 일반 이메일은 HTTP 요청 후 `after()`에서도 발송한다.
4. 신규 요청 유입을 중단하고 진행 중 요청과 후속 발송을 배출한 뒤 구 앱 프로세스를 완전히 종료한다. 구·신 프로세스가 겹치는 rolling reload로 전환하지 않는다.
5. 새 앱을 시작하고 컬럼·CHECK·발송 결과·pending/failed 적체를 확인한다. 기존 `flock`을 유지한 cron을 재개하고 요청 유입을 복구한다.

```bash
rtk proxy psql "$DATABASE_URL" -X -v ON_ERROR_STOP=1 -f scripts/migrations/20261022-outbox-claims.sql
```

기존 일반 이메일 처리기가 `scheduled_at`에 남긴 5분 리스는 그대로 둔다. 시간이 되면 새 처리기가 선점한다. 이를 앞당기는 일괄 UPDATE는 하지 않는다.

## 롤백과 복구

앱 롤백 시 추가 컬럼·CHECK·선점 기록을 삭제하지 않는다. cron과 새 요청 유입을 멈추고 신 앱의 진행 작업을 배출·종료한 다음 구 앱을 시작한다. 구 앱이 시작된 뒤에는 기존 cron `flock`이 다이제스트 중첩을 막는 필수 방어가 된다. 구·신 실행기를 동시에 두지 않는다.

프로세스가 중단된 선점은 만료 후 재시도한다. 소유권이 살아 있는 작업의 token/만료를 수동으로 지우지 않는다. 외부 발송은 성공했으나 로컬 기록이 불명확한 경우 공급자 기록과 멱등 키를 먼저 대조한다.

## 검증

마이그레이션 테스트는 기존 데이터·예약 시각 보존, 재실행, CHECK를 검증한다. repository 테스트는 동시 선점·리스 만료·이전 토큰의 결과 거부를 검증하며, 각 다이제스트 테스트는 동시 실행과 읽음 취소를 확인한다. PostgreSQL의 실제 행 잠금은 로컬 일회용 테스트 DB의 두 세션으로 별도 검증한다. PGlite 통과를 실제 PostgreSQL 경합 검증으로 대체하지 않는다.
