# 1회차 견적 상세 UI — 레퍼런스 조사와 제안

2026-10-20 조사 기록. **이 문서는 설계 근거이며 현재 화면 명세는 SCREEN_DESIGN.md가 소유한다.** 조사 이후 사용자의 진행 승인에 따라 아래 구성을 단일 회차 화면에 적용했다. 수수료는 결제수단을 그룹 제목으로, 등급·과금 기준과 수수료를 두 열로 배치했다.

## 현재 구현에서 확인한 문제

`BidRoundHistory.tsx`의 단일 회차 분기와 CSS를 확인했다.

- `견적 수정 이력`, `총 1회차`, `1회차`, `최신`이 상단에 반복된다.
- 정산·가입 조건과 모든 결제수단·등급 수수료가 동일한 `<dl>` 목록에 이어진다.
- 메모와 첨부는 하단에 바로 나오지만 파일은 이름 링크만 표시한다.
- 여러 회차 비교의 그룹 구분이 단일 회차에는 없어 두 상태의 읽는 방식이 달라진다.

## 공식 레퍼런스

추가 의미 구조 참고: [GOV.UK Summary list](https://design-system.service.gov.uk/components/summary-list/)는 키–값 정보에는 설명 목록, 표 형식 데이터에는 표를 쓰도록 구분한다. 정산 조건은 설명 목록, 결제수단·등급·요율은 표가 맞다.

위 표의 ‘확인한 패턴’은 공식 자료에 근거한다. ‘적용 제안’과 아래 구성은 이 제품에 대한 설계 판단이다. 인증이 필요한 타사 앱을 직접 이용한 사용성 검증은 하지 않았다.

## 추천 구성

### 1. 헤더

- 제목: `견적` — 후속 사용자 결정으로 단일 견적의 회차 표기를 생략한다.
- 구매사 화면에서 PG사명을 한 번 표시한다. PG 화면은 회사명 생략.
- 작성자·제출 시각은 한 줄 메타데이터로 표시하고 좁으면 자연스럽게 줄바꿈한다.
- 단일 회차에서는 `총 1회차`와 `최신` 반복을 줄이는 안을 제안한다. 기존 명세의 최신 표시 유지 규칙을 바꾸는 제안이므로 구현 시 SCREEN_DESIGN.md를 함께 갱신한다.
- 비교 선택기나 ‘비교할 견적이 없어요’ 빈 상태는 필요하지 않다.

### 2. 정산·가입 조건

- `정산 주기`, `정산한도`, `월 보증보험`, `가입비` 네 항목을 한 그룹으로 보여준다.
- 넓은 컨테이너에서는 두 열의 라벨–값 목록, 좁은 컨테이너에서는 한 열로 표시한다.
- 모든 항목을 큼직한 KPI 카드로 만들지 않는다. 숫자는 Nunito, 한글 라벨은 Pretendard를 사용한다.
- `0원`과 미입력 `—`를 구분한다.

### 3. 결제 수수료

- 조건 그룹 아래에 충분한 폭의 표를 배치한다.
- PC: `결제수단 / 등급 또는 과금 기준 / 수수료`. 같은 결제수단은 시각적으로 그룹화한다.
- 모바일: 결제수단 제목 아래 `등급 — 요율` 행을 이어 보여준다. 모든 제공 등급을 기본 공개한다.
- 단일요율은 해당 수단의 값, 건당 수수료는 `원/건` 또는 기존 `건당` 라벨로 단위를 명시한다.
- 커스텀 수단도 동일한 규칙을 따른다. 현재 등급만 표시하거나 임의로 합산하지 않는다.
- 대표 수수료·총액·최저 요율을 임의로 만들어 강조하지 않는다.

### 4. 메모·첨부

- 조건 표와 분리한 보조 섹션으로 배치한다.
- 짧은 메모는 바로 표시한다. 긴 메모만 사용자가 펼쳐 읽을 수 있게 한다.
- 첨부는 문서 아이콘·파일명·크기·열기 링크로 구성한다. 링크 목적과 새 창 열림을 접근성 이름에 제공한다.
- 비어 있으면 각 항목에 짧게 `—`를 표시한다. 대형 빈 상태 카드를 추가하지 않는다.

## 구현 시 확인할 항목

- 단일 회차와 여러 회차가 같은 조건 그룹·필드 순서를 유지하는지.
- 320/390px 모바일, 560px 좁은 모달, PC에서 긴 회사명·커스텀 수단·파일명이 넘치지 않는지.
- 미입력/0, 단일/등급별/건당/커스텀 수수료가 모두 정확히 표현되는지.
- 메모 길이와 첨부 유무, 키보드 조작, 라이트/다크.
- 단일 회차 제목과 중복 메타데이터 제거에 대한 테스트를 먼저 실패시킨 뒤 구현할 것.
