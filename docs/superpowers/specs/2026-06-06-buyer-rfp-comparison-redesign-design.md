# 구매사 견적 비교 UX 재설계 — 설계 문서

- **작성일**: 2026-06-06
- **대상 화면**: `/rfp/[id]` (구매사 RFP 상세 — B4), 부수적으로 `/rfp/[id]/award` (B5)
- **상태**: 설계 합의 완료 (브레인스토밍 산출물). 구현 계획은 별도 plan 문서로.

---

## 1. 문제

구매사가 받은 견적(bid)을 비교·선정하는 현재 화면은 **표(`BidComparisonTable`) ↔ 보드(`RfpBidsBoard`) 토글**로 되어 있다. 표는 PG × 지표를 빽빽한 스프레드시트로 보여줘 한눈에 결정을 돕지 못하고(정보 과잉), 보드는 칸반 단계 워크플로우라 "비교"라는 본질과 어긋난다. 결과적으로 **무엇을 봐야 결정되는지**가 흐리다.

## 2. 목표 / 비목표

**목표**
- 표·보드를 들어내고 **포커스(한 번에 한 견적 깊게) + hover 비교** 구조로 전면 교체
- **강조 정보 하나**에 집중 — "지금 조건 대비 얼마나 좋아지나"(개선 요약)를 주인공으로
- **아코디언으로 부차 정보를 접어** 공간 효율과 시선 집중 확보
- 표가 하던 **교차 비교 능력은 "값 단위 hover"로 온디맨드 복원**

**비목표**
- 견적 데이터 스키마 변경 (bid 필드 그대로 사용)
- 구매사 "현재 조건" 필드를 구조화(숫자화)하는 작업 — 자유 텍스트·선택 입력 그대로 두고 best-effort로만 활용
- 공용 칸반 인프라(`KanbanBoard`/`PipelineBoard`, RFP 목록·PG inbox 보드) 변경
- `awardRfpAction` 서버 로직 변경 (UI 진입만 인라인화)

## 3. 확정 결정 (브레인스토밍 합의)

1. **레이아웃**: 포커스 스포트라이트 — 상단 탭으로 PG 전환, 본문에 한 견적만 크게.
2. **탭 hover peek**: 다른 PG 탭에 hover 시 그 PG 요약(강조 숫자 + 정산주기·한도)을 작은 카드로 미리보기. 클릭하면 전환.
3. **강조(hero) = 개선 요약**: `현재 조건 → 제안값` 화살표 + 개선폭. 비교 가능한 현재값은 **카드 수수료·월 정산한도·보증보험 3개뿐**(RFP에 "현재 정산주기" 필드 없음 → 정산주기는 제안값만 헤더에 표기).
4. **값 단위 hover 비교**: 구조화된 비교 가능 값(카드 수수료·정산한도·보증보험·정산주기·각 결제수단 요율)에 hover 시 **그 지표로 전 PG가 좋은 순으로 줄세워지는 팝오버**. 현재 조건이 있으면 기준선으로 같이 표시. **팝오버의 다른 PG를 클릭하면 그 PG로 포커스 전환.** 자유 텍스트(메모·PDF)는 비교 대상이 아니라 hover 없음.
5. **범위**: 비교 섹션뿐 아니라 **상세 페이지 전체 IA**를 아코디언 중심으로 재구성.
6. **PG별 메모**: 보드 모달에만 있던 `BidNotesPanel`(구매사 비공개 메모/첨부)을 **포커스 뷰 '내 메모' 아코디언으로 이전** (제거 아님).
7. **칸반 단계**(진행전/협상중/결정): **제거**. `bids.board_column_id` 컬럼은 잔존시키되 이 화면에서 사용 안 함(스키마 마이그레이션 없음).
8. **선정 확정**: **인라인 확정 다이얼로그**. `/rfp/[id]/award` 별도 페이지로의 이동을 없애고, 포커스 뷰의 CTA가 모달로 확정. `awardRfpAction` 재사용.

### 4.1 탭 hover peek vs 값 hover 비교 (두 층)
- **탭 hover** → 그 PG 통째 요약 미리보기(전환 후보). 클릭 = 포커스 전환.
- **값 hover** → 그 지표 하나로 전 PG 줄세움 + 현재 조건 기준선. 팝오버 내 PG 클릭 = 포커스 전환.

### 4.2 개선 요약(hero) 데이터 상태별 동작
- **현재 조건 다 입력**: 3행 모두 `현재 → 제안 + 개선폭`.
- **일부만 입력**: 입력된 행만 화살표·개선폭, 나머지는 제안값만.
- **전혀 없음**: "핵심 수치" 요약으로 강등(제안값만). (선택: "현재 조건을 입력하면 개선폭을 보여드려요" 안내 — 구현 시 결정)
- **개선폭 배지**(↓0.60%p)는 현재값이 **숫자로 파싱될 때만**. "협의 가능" 등 자유 텍스트면 병기(`2.80% → 2.20%`)만, 배지 생략.

### 4.3 아코디언 기본 펼침 규칙
- '내가 요청한 조건' / 'PG 초대·게시판 관리' 모두 기본 **접힘**.
- 단, **받은 견적 0건 OR 콜드피치 대기 > 0** 이면 'PG 초대·게시판 관리' **자동 펼침** + 헤더 배지(`대기 N건`).

### 4.4 상태별 화면
- `sent` + bids>0: 평상시(비교·선정 가능).
- `sent` + bids=0: 비교 영역에 빈 상태("견적을 기다리고 있어요"), 'PG 관리' 자동 펼침.
- `awarded`/`closed`: 선정 CTA 숨김, 승자 강조 + 선정/미선정 배지, 다이얼로그 비활성.
- bids=1: 포커스 뷰 정상 동작. 값 hover 비교는 그 1건 + 현재 조건만 표시.

## 6. 데이터 흐름 / 계산

- 로더 `loadBuyerRfpDetail`이 이미 `bids`·`notesByBid`·`pgWsNameMap`·rfp 현재조건을 제공 → **추가 fetch 없음**.
- **값 비교 줄세움은 클라이언트 계산**: bids 배열로 지표별 정렬·best 산출.
  - 수치 지표(카드 수수료·각 결제수단 요율·정산한도·보증보험): 숫자 비교.
  - 정산주기: `compareSettleCycle` 재사용.
  - 방향성(낮을수록/높을수록 좋음)을 지표별로 정의해 정렬·"이 견적" 강조.
- **현재 조건 파서**(신규 유틸): 자유 텍스트(`current_fee_rate` 등)에서 best-effort 숫자 추출. 성공 시 개선폭 계산, 실패 시 병기만. 순수 함수 → 단위 테스트.
- 인라인 다이얼로그는 화면에 이미 있는 bid로 충분 → `loadBuyerAwardData` 불필요.

## 7. 모바일 / 접근성

- **터치(hover 없음) 폴백**: 탭 탭 = 바로 전환(peek 생략). 값 탭 = 비교를 바텀시트/팝오버로.
- 팝오버·아코디언은 `@base-ui/react` 컴포넌트라 키보드·포커스 트랩·`aria` 기본 제공.
- 모션은 transform/opacity만(Linear 규칙), 펼침 100ms대.

## 8. 디자인 규칙 (Linear) 정합

- 팝오버/다이얼로그는 floating 요소라 큰 그림자 허용(예외 규칙). 아코디언·탭·행 경계는 `outline-variant` 헤어라인.
- 모든 수치는 `.md-numeric`(mono + tabular-nums). 상태는 `Chip`(괄호 텍스트 금지).
- pill 버튼 금지(6px), hover는 배경 명도 시프트만.

## 11. 미해결 / 구현 중 결정

- 현재 조건이 전혀 없을 때 "현재 조건 입력 유도" 안내 노출 여부 (소소 — 구현 시 결정).
