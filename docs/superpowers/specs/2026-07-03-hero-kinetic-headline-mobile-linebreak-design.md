# 히어로 순환 헤드라인 모바일 줄바꿈 안정화

## 배경

`components/landing/hero/HeroKineticHeadline.tsx`의 히어로 헤드라인은 "Supporter B를 통해" +
`ScrambleText`로 순환하는 5개 문구 + "만듭니다."를 한 줄(`flex flex-wrap`)에 흘려 렌더링한다.
순환 문구 5개는 길이가 서로 다르다(`협상의 주도권을` 8자 ~ `정보 비대칭 없는 계약을` 12자).
모바일 폭에서는 문구가 바뀔 때마다 줄 수가 1줄↔2줄로 바뀌며 헤드라인 블록 높이가 들썩인다.

## 목표

- 모바일에서 순환 애니메이션 중 줄 수/레이아웃이 변하지 않게 한다.
- 데스크톱(`md:` 768px 이상)의 현재 시각적 결과는 그대로 유지한다.

## 변경 범위

`components/landing/hero/HeroKineticHeadline.tsx`만 수정. `ScrambleText.tsx`는 `className`으로
`whitespace-nowrap`을 전달받는 것 외에 로직 변경 없음.

## 설계

### 1. 반응형 레이아웃 분리 (CSS만, JS 분기 없음)

기존에는 순환 문구 + "만듭니다."를 감싸는 컨테이너가 `flex items-baseline flex-wrap` 한 종류였다.
이를 아래로 변경한다.

```
flex flex-col md:flex-row md:flex-wrap md:items-baseline md:gap-x-2
```

- `md:` 이상: `flex-row` + `flex-wrap`으로 기존과 동일한 한 줄 흐름 유지.
- `md:` 미만(모바일/태블릿 세로): 기본값 `flex-col`로 자동 전환 — 순환 문구와 "만듭니다."가
  각자 독립된 줄이 되어, 문구 길이가 다른 줄의 줄바꿈 여부에 영향을 주지 않는다.

동일 마크업에서 Tailwind 반응형 변형만으로 두 레이아웃을 표현하므로 `ScrambleText`를
중복 마운트하지 않는다(리소스 낭비·상태 이중화 방지).

### 2. 마스크 리빌 분리

현재 순환 문구 + "만듭니다."는 하나의 `overflow-hidden` 마스크 + `motion.div`(같은 딜레이
`0.32`)로 함께 리빌된다. 이를 각 줄마다 독립된 마스크로 분리한다(`MaskedLine` 헬퍼,
기존 `MaskedWord`와 동일한 패턴 — `overflow-hidden` + `pb/-mb` 여유 + `y:'112%'→0`).

두 `MaskedLine` 모두 동일한 `delay={0.32}`를 사용하므로:
- 데스크톱(한 줄 흐름): 두 조각이 동시에 위로 올라와 기존과 시각적으로 동일하게 보인다.
- 모바일(줄 분리): 두 줄이 각자의 마스크 안에서 동시에 리빌된다 — Line 1의 단어별
  마스크 리빌과 같은 언어로 일관된 모션.

### 3. 간격 처리

기존에는 순환 문구 뒤에 `&nbsp;만듭니다.`로 한 줄 안에서만 필요한 간격을 텍스트 노드에
넣었다. 모바일에서 줄이 분리되면 이 `nbsp`가 불필요한 들여쓰기로 보인다. `nbsp`를 제거하고
컨테이너의 `md:gap-x-2`로 데스크톱 간격을 대체한다.

### 4. 순환 문구 자체의 줄바꿈 방지

줄을 분리해도 문구 자체가 좁은 화면에서 내부 공백(예: "정보 비대칭 없는 계약을") 때문에
2줄로 꺾일 수 있다. 두 가지를 함께 적용한다.

- `ScrambleText`에 `whitespace-nowrap` 클래스를 추가로 전달해 문구 내부에서 줄바꿈이
  일어나지 않게 강제한다(정착 상태·스크램블 상태 모두 동일한 outer `<span>`에 적용되므로
  한 곳에서 처리된다).
- `headlineCls`에 모바일 전용 폰트 크기 상한을 추가한다:

  ```
  text-[clamp(30px,5.5vw,72px)] max-md:text-[clamp(22px,7.2vw,34px)]
  ```

  데스크톱 값은 그대로 두고, `md:` 미만에서만 더 낮은 상한(34px)과 더 낮은 하한(22px)을
  적용해 320~430px 폭에서 가장 긴 문구(12자)도 한 줄에 들어가도록 여유를 확보한다.
  Line 1과 "만듭니다."도 같은 `headlineCls`를 공유하므로 모바일에서 헤드라인 전체가
  약간 작아지며 크기 통일감을 유지한다(두 텍스트는 원래도 짧아 줄바꿈 위험이 없었다).

### 5. 검증

이 변경은 스타일/마크업만 다루고 JS 상태·분기 로직을 추가하지 않으므로 프로젝트
TDD 규칙상 면제 대상이다(CLAUDE.md "시각/스타일만 손대는 변경"). 브라우저에서 320px,
375px, 430px 폭으로 리사이즈하며 5개 문구가 순환하는 동안 줄 수·레이아웃이 안정적인지
육안으로 확인한다. 폰트 크기 수치가 실측 결과 부족하면(예: 여전히 2줄로 꺾이는 문구가
있으면) `max-md:` clamp 값만 조정한다. 데스크톱은 기존 화면과 픽셀 단위로 동일해야 한다.

## 비범위 (Out of scope)

- `SolutionShowcase`, `ProblemCard`, `MetricCard` 등 다른 랜딩 애니메이션 텍스트는 이번
  변경에 포함하지 않는다(브레인스토밍 중 사용자가 히어로 헤드라인으로 범위를 확정).
- `ScrambleText`의 스크램블 로직(글리프 전환·지터) 자체는 변경하지 않는다.
