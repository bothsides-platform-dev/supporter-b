# NineHire 채팅 UI 정합 레퍼런스 (스크린샷 기반)

> 출처: 사용자 제공 NineHire(app.ninehire.com) 스크린샷 4장. UI 단계(7) 에이전트가 이미지를 볼 수 없으므로
> 그 화면을 텍스트로 옮긴 명세. **목표: 레이아웃·인터랙션을 "그대로"** 재현하되 우리 백엔드(워크스페이스 페어
> 풀 IM, 평문 메시지, 템플릿/첨부)와 어긋나는 부분은 "우리 적용"으로 명시.

## NineHire 화면 구조 (관찰)

NineHire는 지원자 상세 안에 두 종류의 대화면이 있다:
1. **연락 내역(center 탭)** — 채용담당자 ↔ 지원자(외부). 이메일+채팅을 한 히스토리에 말풍선으로 섞어 표시.
   상단에 `메일 보내기` / `채팅 메시지 보내기` 버튼 → 우측 **작성 드로어**로 작성. 스레드 자체엔 하단 인라인
   컴포저가 없음(드로어 기반).
2. **팀 채팅(right 탭)** — 내부 팀원끼리. 하단 **인라인 컴포저** + 대상 범위(전체/매니저/채용관리자) + @멘션.

**우리 매핑**: 우리 채팅은 구매사↔PG(외부 양자) → **연락 내역**이 대응 모델. 팀 채팅(내부)은 범위 밖.
단 우리는 "풀 IM(타이핑/프레즌스/라이브)"을 택했으므로 **하단 인라인 컴포저(팀 채팅식 빠른 입력)** +
**리치 작성 드로어(연락 내역식, 템플릿/첨부/알림)** 를 **둘 다** 둔다(NineHire도 두 컴포저가 공존).

## 1) 대화 스레드 (ThreadView 재작업)

- **말풍선**: 받은 메시지 = **좌측 정렬, 회색 라운드 버블**(`surface-container`). 보낸 메시지 = **우측 정렬**
  (현재 목은 primary 파랑 — NineHire는 보낸 것도 옅은 회색/화이트 계열에 가까움. **우리 적용: 보낸 버블은
  옅은 회색 유지하되 Linear 토큰으로**; primary 파랑 과사용 지양).
- 각 버블 위/옆: **발신자 아바타 + 이름 + 시각**(예 "남한솔 오후 10:38"). 연속 메시지는 헤더 생략 가능.
- 보낸 메시지 하단: **읽음 영수증** "읽음 ✓" (상대 `last_read_at >= 메시지시각`일 때). 라이브 갱신.
- **날짜 구분선**: 가운데 "5월 26일 화요일" 형태 divider.
- (NineHire의 "메일 ▼" 채널 배지) → **우리 적용**: 우리 메시지는 인앱 채팅 단일 종류이므로 채널 배지 불필요.
  단 메시지에 RFP 컨텍스트가 있으면 **RFP 코드 칩**(`P-2605-0042 · 제목`)을 버블 또는 헤더에 표시(스펙 모델).
- 상단 헤더: 상대 워크스페이스 아바타 + 이름 + 타입 Chip + (있으면) RFP 링크. + **프레즌스 점**(온라인),
  **타이핑 인디케이터**("입력 중…")는 스레드 하단/헤더에.

## 2) 하단 인라인 컴포저 (빠른 입력 — 풀 IM)

- textarea(자동 높이, Shift+Enter 줄바꿈) + 좌측 **첨부(클립)** + 우측 **보내기**.
- 입력 중 타이핑 이벤트 publish(디바운스). 전송 시 `sendChatMessageAction`.
- (현재 목의 disabled 클립/보내기→ComingSoon 제거.)

## 3) 리치 작성 드로어 (MessageComposeButton + 스레드 상단 "메시지 보내기")

NineHire `채팅 메시지 보내기` 드로어를 기준으로(우측 Sheet):
- 제목줄: "○○에게 메시지 보내기" + 도움말 아이콘, 접기/닫기.
- **저장된 템플릿 불러오기** (collapsible dropdown) — `listTemplatesAction`로 채우고 선택 시 본문 삽입.
  "현재 작성 내용을 템플릿으로 저장"(`saveTemplateAction`) 액션도 제공.
- 보내는 사람(현재 사용자), **파일 첨부**(`파일 선택`) — **우리 적용: 최대 5개·20MB**(NineHire 50MB 아님,
  Caddy 25MB 캡). 첨부 칩 리스트 + 제거.
- 본문 입력 영역 + placeholder "상대에게 보낼 메시지를 입력하세요".
- 하단: **알림 발송 토글 — ✅ 이메일 / ✅ 인앱**(NineHire의 이메일/알림톡 → 우리는 이메일+인앱; 알림톡은 후속).
  **바로 전송** 버튼 (+ **예약 전송** 시계 — 아래 "적용 범위" 참조).
- 임베드 진입점(RFP 상세·입찰표의 `MessageComposeButton` 3곳): 클릭 → 이 드로어. 해당 RFP를 `rfpId` 태그로
  자동 첨부. `ComingSoonDialog` 제거.

## 4) 인박스 목록 (ConversationList)

- 좌측 리스트: 상대 워크스페이스 아바타 + 이름 + 최근 메시지 미리보기 + 시각 + **미읽음 점/뱃지**
  (`last_read_at` 기반, 라이브 갱신). RFP 코드 보조 표기.
- 선택 시 우측 ThreadView. (현재 SplitView 골격 유지.)
- **새 대화** 진입: 상단 버튼 → 기존 RFP 연결 상대 목록 + 이메일 입력(콜드 컨택).

## 적용 범위 — "그대로" vs 백엔드 정합 (UI 단계 착수 전 확인 필요)

직접 매핑(바로 구현):
- 말풍선 스레드 + 읽음 영수증 + 날짜 구분선 + 프레즌스/타이핑 ✅(백엔드/Centrifugo 준비됨)
- 저장 템플릿 불러오기/저장 ✅(`chat_message_templates`)
- 파일 첨부 ✅(첨부 exclusive-arc; 5개/20MB)
- 이메일/인앱 알림 토글 ✅(outbox/dispatch)

확장 — **확정(사용자 결정)**:
- **메시지 본문 = 평문 (v1 확정)**: 줄바꿈 + URL 자동링크만. 리치 HTML은 후속(저장형식·sanitize 필요).
  `chat_messages.body` 평문 유지 — 백엔드 변경 없음. 에디터는 자동높이 textarea.
- **개인화 변수**(`{지원자}` 류): **v1 보류**(워크스페이스 페어 대상이라 효용 적음).
- **예약 전송**(scheduled send): **v1 보류**(아이콘 노출 안 함). outbox `scheduledAt`로 후속 가능.
- **일정 조율 / 자료 요청 모듈**: **범위 밖(미구현)**.
- **메일 vs 채팅 send-type 선택기**: **불필요**(메시지는 인앱 단일 종류, 이메일은 알림). 단일 작성 드로어.

## Linear 디자인 정합 (DESIGN.md Hard Rule)

NineHire 비주얼을 참고하되 **우리 토큰/규칙 준수**: pill 금지(6px shape-small), 그림자 승격 금지, 저대비
`outline-variant` 보더, body ≤14px, `.md-numeric`(시각·코드), Chip 컴포넌트(상태), 모션 transform/opacity만.
즉 "NineHire 레이아웃·인터랙션"은 따르되 색·타이포·보더는 Linear로 치환.
