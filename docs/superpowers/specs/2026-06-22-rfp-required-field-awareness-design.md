# 구매사 견적 요청 — 필수값 인지 강화 설계

작성일: 2026-06-22

## 문제

구매사가 견적 요청(RFP)을 작성할 때, 어떤 값이 필수인지 그리고 내가 아직 무엇을
비워뒀는지를 **작성 중에는** 알 수 없다. 현재는 라벨의 `*` 표시와, "다음"을 눌렀을
때 뜨는 토스트로만 알려준다. 사용자는 한 단계를 다 쓴 뒤에야 무엇이 빠졌는지 알게 된다.

추가로, 현재 스텝 완료 판정(사이드바 녹색 체크를 켜는 로직)이 필수값과 어긋나 있다.
Step 2 완료는 제목·홈페이지 형식만 보고 **결제수단은 제출 시점까지 검사하지 않아서**,
결제수단이 비어 있어도 스텝 체크가 녹색으로 켜질 수 있다.

## 목표

각 필수 필드의 충족 여부를 작성 중에 실시간으로 인지할 수 있게 한다. 마커(필드 단위),
스텝 체크(사이드바/프로그레스), "다음" 막기 — 세 신호가 **언제나 같은 진실**을
가리키게 만든다.

비목표: "다음" 버튼 비활성화(기존 디자인 철학은 버튼을 항상 활성 유지). 선택 필드에
대한 권장 유도(이번 범위는 시스템 필수값 한정).

## 필수 필드와 유효 기준 (5개)

| 필드 | 위치 | 유효 기준 |
|---|---|---|
| 제목 | Step 2 | `title.trim().length > 0` |
| 홈페이지 | Step 2 | 비어있지 않음 **AND** `isValidWebsiteUrl` 통과 |
| 견적 받을 결제수단 | Step 2 | 선택 + 직접입력 합이 1개 이상 |
| 초대할 PG사 | Step 3 | 1개 이상 선택 |
| 마감일 | Step 4 | 유효 날짜 **AND** 내일(KST) 이후 |

홈페이지는 이번에 **선택 → 필수**로 승격된다. 비었을 때와 형식이 틀렸을 때 메시지를
구분한다.
- 비었을 때: `홈페이지 주소를 입력해주세요`
- 형식 오류: `홈페이지 주소 형식을 확인해주세요` (기존 메시지 유지)

홈페이지 필수화는 검증 규칙 변경이므로 클라이언트와 서버 양쪽을 함께 고친다. (오픈
게시판이 홈페이지를 공개 노출하므로 필수화는 도메인 결에도 맞다.)

## 필드 단위 마커 — 3가지 상태

각 필수 필드 라벨 옆에 작은 상태 칩을 항상 둔다. 입력값에 따라 실시간 전환한다.

| 상태 | 조건 | 표현 (Linear 규칙 준수) |
|---|---|---|
| 미입력 | 아직 유효값 없음 | 중립(surface) 칩 `필수` — 저대비, 차분하게 |
| 입력 완료 | 유효값 들어옴 | tertiary 칩 + `Check` 아이콘 |
| 오류 | "다음" 눌렀는데 무효 | 기존 red 처리(red border + 메시지) + 칩 error 톤 |

핵심은 **미입력 → 입력 완료** 전환이 토스트 없이 작성 중에 즉시 보인다는 점이다.
red(오류)는 지금처럼 next-click 실패에만 쓰고, "아직 안 채움"은 중립 톤으로 분리해
폼이 처음부터 잔소리하는 느낌을 피한다.

홈페이지 주소는 *형식* 검증 필드이므로 마커 "입력 완료"는 형식까지 통과해야 켜진다.

## 스텝 완료 = 그 단계 필수 판정의 AND

스텝 완료 여부(사이드바 녹색 체크)를 SSOT 판정 함수의 곱으로 재정의한다.

| 스텝 | 완료(녹색 체크) 조건 |
|---|---|
| Step 2 | `isTitleValid && isWebsiteValid && isPaymentValid` |
| Step 3 | `isPgValid` |
| Step 4 | `isDeadlineValid` |

필수가 하나라도 비면 그 스텝은 미완료로 남아 녹색 체크가 켜지지 않는다. 마커도 해당
필드만 "미입력", "다음"도 막힌다 — 세 신호가 같은 진실을 가리킨다.

## 컴포넌트 / 데이터 구조

- **`lib/rfp/required-fields.ts` (신규, 순수 모듈)** — 단일 출처(SSOT).
  - `isTitleValid`, `isWebsiteValid`, `isPaymentValid`, `isPgValid`, `isDeadlineValid`
  - 5개 순수 함수. DB·React 의존 없음.
- **`wizard-validation.ts` (리팩터)** — 위 함수를 import 해서 스텝 완료/토스트 메시지
  를 도출한다. 중복 판정 로직 제거. Step 2 완료에 `isPaymentValid` 추가(현재 누락).
- **`RequiredMark` 컴포넌트 (신규, 프레젠테이션)** — `state: 'empty' | 'filled' |
  'error'`를 받아 기존 Chip 컴포넌트로 렌더. 시각 전용.
- **각 Step 컴포넌트** — 드래프트 스토어 값으로 필드별 판정 함수를 호출해
  `RequiredMark` 상태를 결정. `error` 상태는 기존 `failedSteps`(해당 스텝이 실패로
  마킹) AND 필드 무효일 때.
- **`createRfpAction` (서버)** — zod 스키마에서 `website`를 required + 형식검증
  (`isValidWebsiteUrl`)으로 승격.

## 영향 / 주의

- 홈페이지 필수화로 기존 테스트·픽스처(샘플/데모 RFP 생성 포함) 중 홈페이지 없이
  RFP를 만드는 경로가 깨질 수 있다 → 픽스처에 유효 홈페이지 추가 필요.
- 드래프트 스토어 스키마는 변경 없음(홈페이지 필드는 이미 존재).
- 기존 RFP 데이터에는 영향 없음(작성 시점 검증만 강화).
