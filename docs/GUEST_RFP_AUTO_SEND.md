# 비로그인 견적 자동 요청

사용자가 PG와 3·5·10영업일 응답 기간을 선택하고 자동 요청을 확정한 초안만 대상이다. 기존 초안에는 동의를 소급 적용하지 않는다. 절감 계산기는 유지한다. 가입 폼과 이메일 인증은 같은 견적 화면에서 진행하며, 실제 견적 생성 전에는 성공 효과를 실행하지 않는다.

## 저장·처리 경계

`guest_rfp_requests`는 초안 revision, 선택 PG, 응답 기간, 확정 시각, 계정 연결 후 30일 만료, 처리 상태와 효과 확인 시각을 저장한다. 소유자는 연결된 `guest_rfp_drafts`의 사용자·워크스페이스다. 기존 계정 연결에는 심사 신청을 새로 만들지 않는다.

예약의 변경과 효과 선점은 초안 행을 먼저 잠근 뒤 예약 행을 읽고 갱신한다. 초안 행 잠금이 같은 초안의 수정·취소·발송을 직렬화한다. 예약 중 답변 변경은 차단하며, 취소 후 다시 확정한다. 인증·활성 구매사·실효 멤버십·유효기간·답변·첨부·선택 PG를 발송 전에 확인한다. 발송일 다음 날부터 한국 영업일을 계산하고 마감은 18:00 KST다. 달력 미적재·일시 장애는 재시도하고 유효기간을 늘리지 않는다. 선택 PG 불가·답변 및 첨부 무효는 `needs_action`이며 다른 PG를 자동 선택하지 않는다.

기존 견적 생성 서비스의 트랜잭션을 호출자가 전달할 수 있게 하여 첨부 인계, 견적, 초안 완료, 예약 완료, 구매사 앱 알림 및 완료 이메일을 함께 커밋한다. PG 초대·알림은 기존 생성 경로를 사용한다. 실시간 발행과 outbox 실행은 외부 트랜잭션 커밋 이후다. 처리 시도 시각 순서로 순환해 미인증 대기 건이 뒤의 요청을 가리지 않는다.

## 완료 안내

`rfp.auto_sent` 앱 알림은 요청 사용자에게 해당 구매사 워크스페이스에서 한 번 생성한다. 기존 알림 목록·배지·읽음 처리를 사용한다. 효과 확인은 별도 `effect_seen_at`으로 관리하며 사용자 소유권과 초안 행 잠금으로 원자 선점한다. 작성 화면은 완료 제목으로 초점을 옮기고 공용 브랜드 컨페티를 실행한다. 모션 감소에서는 정적 체크와 문구만 표시한다. 앱 셸은 모바일 메뉴 상태와 무관하게 실시간 알림을 구독하고 포커스 복귀·주기 조회로 누락을 보완한다.

## 배포·복구

1. `scripts/migrations/20261025-guest-rfp-requests.sql`을 먼저 적용한다. 기존 계정 연결을 위해 초안의 심사 신청 ID는 선택 값으로 바뀐다.
2. `GUEST_RFP_AUTO_SEND_ENABLED=false`로 앱을 배포한다. DDL은 기능 비활성 상태에서도 선행해야 한다.
3. 기존 `CRON_SECRET`을 사용해 아래 cron을 등록한다.
4. 달력 coverage, 가입·인증·입점 승인, 요청 생성과 알림을 확인한 뒤 `GUEST_RFP_AUTO_SEND_ENABLED=true`로 재시작한다.

```cron
* * * * * flock -n /tmp/dispatch-guest-rfp.lock curl -fsS --max-time 55 -X POST http://localhost:3000/api/cron/dispatch-guest-rfp -H "x-cron-secret: $CRON_SECRET"
```

중지 시 기능 변수를 false로 바꾸고 앱을 재시작한다. 대기 행과 원래 만료 시각을 보존한다. 재개는 true로 변경한 뒤 cron을 다시 실행한다. 이미 완료한 견적은 취소·재발송하지 않는다. 롤백 때 새 테이블이나 연결 기록을 삭제하지 않는다. 운영 배포와 cron 등록은 이 문서 작성만으로 실행되지 않는다.

## 구현 검증 기록 (2026-10-25)

- 전체 단위 테스트: 9,128개 통과, 10개 기존 skip. 마지막 만료 예약 취소 보완 후 관련 서비스 테스트 43개를 재실행해 통과했다.
- 타입 검사·lint·프로덕션 빌드 통과. 빌드는 테스트 DB와 발송 불가능한 외부 서비스 설정으로 실행했다.
- 신규 화면 E2E: 모바일 390px·데스크톱 1280px 모두 통과. 상태 API를 제어해 PG·워크스페이스 선택, 실제 완료 상태 전 성공 미표시, 제목 초점, 상세 링크, 모션 감소, 새로고침 후 효과 미반복을 검증했다. 서버의 생성·첨부 인계·가입 연결·알림 원자성과 동시 실행은 PGlite 통합 테스트로 검증했다.
- 기존 전체 E2E는 124개 통과·6개 skip·6개 실패였다. 견적 상세·선정과 다른 기기 이메일 인증은 개별 재실행에서 통과했다. 테마 색상 관련 3개 실패는 변경 전 커밋 `0e334f8b`에서도 재현됐다. 전체 E2E가 모두 통과한 상태는 아니다.
- 실제 SMS·이메일·R2 연동을 포함한 운영 가입과 발송, 운영 DDL·cron·기능 활성화는 실행하지 않았다.
