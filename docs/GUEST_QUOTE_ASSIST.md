# 공개 견적 자동 입력과 맞춤 절감액

2026-10-29 결정. 범위는 /quote-start와 구매사 가입 인계다. 회원 작성·튜토리얼·랜딩 계산기는 기존 동작을 유지한다.

## 작성 흐름

사업자번호(건너뛰기 가능) → 직접 입력한 홈페이지 → 제안 확인·수정 → 부족한 질문 → 맞춤 절감액 → 가입이다. 사업자 조회·규칙 추출·AI 보완은 각각 독립적으로 보존한다. 사용자가 확인한 유효 답변만 질문에서 제외한다. 업종은 정확히 일치하는 등록 목록만 제안하며, 판매 방식·배송 기간·입점 판매자·환금성 상품은 원문 근거가 있는 경우만 제안한다. 값이 없다고 아니요로 추정하지 않는다. 금액·최고 가격대·계약 유형·현재 PG·희망 결제수단은 직접 확인한다.

제목은 회사명·주요 상품·신규/갱신으로 만들며 AI를 사용하지 않는다. 회사명이 없으면 ‘우리 회사’를 쓴다. 가입 인계는 현재 초안 ID와 사업자번호에 묶인 회사명·번호 제안이며, 국세청 확인·서버 가입 검증·승인 정책을 대체하지 않는다.

분석 중에도 ‘직접 입력할게요’를 제공한다. 중단 후 도착한 응답은 세대 번호로 무시하고 새로고침 시 자동 재분석하지 않는다. 번호·URL 변경은 해당 출처의 제안과 확인 상태를 무효화한다. 사용자 수정값은 우선한다. AI 미설정·실패·잘못된 JSON·근거 없는 필드는 기존 조회·규칙 결과를 지우지 않는다.

## 계산 계약

QuoteSavingsService는 저장된 계약 유형·업종·현재 PG·현재 카드 수수료와 사용자가 별도로 확인한 매출 구간·카드 거래액·부가세 기준으로 계산한다. 추천 순서·접수 불가 업종·비활성 PG·기존 PG 제외는 기존 매칭 repository를 공유한다. 첫 후보를 기본 비교하고 비교/상담 PG를 바꾸면 다시 계산한다.

잠정 등급은 연매출 3억 이하 영세, 5억 이하 중소1, 10억 이하 중소2, 30억 이하 중소3, 초과 일반이다. 신규는 예상 연매출임을 표시한다. DB의 승인 등급을 변경하지 않는다.

- 갱신: 연간 카드 거래액 × (기존 수수료율 − 제안 요율) ÷ 100.
- 신규: 예상 연간 카드 거래액 × (동일 PG·잠정 등급 표준 요율 − 제안 요율) ÷ 100. ‘표준 요율 대비 예상 절감액’으로 표시한다.
- 매칭 정책은 퍼센트(1 = 1%), 합의서 표준 요율은 소수(0.01 = 1%)다. 표준 요율은 기존 합의서 계약대로 부가세 별도다. 매칭 feeNote에 ‘부가세 별도’ 또는 ‘부가세 포함’이 명확히 있어야 계산하며, 포함 요율과 포함 현재 수수료는 1.1로 나눠 별도 기준으로 통일한다. 모호하거나 양쪽 표현이 모두 있으면 산정을 보류한다. 운영자는 숫자뿐 아니라 해당 조건도 확인한다.
- 연간·월평균은 반올림 전 금액으로 각각 원 단위 반올림한다. 카드 외 수단·가입비·보증보험은 제외한다.
- 수치·요율 부족 시 금액을 만들지 않고 신청은 허용한다. 차이가 0 이하이면 절감 효과 미확인을 안내한다. 양의 서버 결과만 카운트업·브랜드 블루 폭죽을 사용하고 감소 모션에서는 최종 숫자만 표시한다.

## 인터페이스와 보관

공개 POST /api/guest-rfp/assist와 /api/guest-rfp/savings는 기존 초안 HttpOnly 증명, 동일 buyer Origin/Host, 제한된 JSON body, revision을 확인한다. 첫 분석 전 기존 drafts/session·save로 서버 초안을 만들고 반환 revision을 이후 저장에 사용한다. 분석·절감액·가입 저장은 같은 브라우저 저장 큐를 공유한다. 초안 ID만으로 조회할 수 없고 가입 연결 후에는 공개 증명이 더 이상 유효하지 않다.

answers JSONB envelope의 선택적 quoteContext v1에 회사 정보·제안 출처·사용자 수정/확인 상태·작성 위치·산정 입력/결과를 저장한다. 브라우저 및 서버 저장값은 비신뢰 참고 정보다. 계산은 서버가 요율을 다시 조회하며 클라이언트가 저장한 결과를 승인·견적 요율에 사용하지 않는다. 기존 quoteContext 없는 초안은 기존 작성 위치로 복원한다. 회원 저장은 이 문맥을 보존한다.

미가입 초안은 마지막 저장 후 24시간, 가입 연결본은 요청 완료·삭제·탈퇴까지 보존한다. 완료·삭제 때 문맥과 조회 캐시를 비운다. guest_quote_calls는 입력 해시별 결과·비용·시각만 최대 24시간, guest_quote_ip_budget은 원 IP 대신 시간 버킷별 SHA-256 키를 최대 1시간 저장한다. 기존 sweep-uploads cron이 만료 행을 청소한다. 홈페이지 원문·APICK 원본·대표자명·요청 헤더·전체 요율표는 저장하거나 공개하지 않는다.

## 네트워크·호출 한도

홈페이지는 HTTP(S) 기본 포트·동일 호스트 공개 페이지 최대 3개, 전체 DNS/응답/본문 수집 6초, 페이지별 256KiB다. 사설·예약 IP와 혼합 DNS 응답을 거부하고 검증한 접속 IP를 고정한다. 리다이렉트마다 같은 검사를 적용한다. 쿠키·사용자 인증을 전달하지 않고 스크립트·페이지 지시를 실행하지 않는다.

AI는 공개 페이지의 제한된 텍스트와 필요한 업종 목록만 받는다. APICK LLM 공식 명세: https://apick.app/dev_guide/llm_chat. 기본 DeepSeek 모델과 추론 설정을 환경변수로 관리하며 헤더·본문을 합쳐 8초다. 자동 재시도 없이 프로세스별 연속 3회 실패 시 60초 중단하고 하나의 시험 호출로 복구한다. PM2 재시작 시 이 일시 중단 상태는 초기화되지만 DB 호출 예산은 남는다.

유료 호출 선점은 부모 초안 잠금과 PK로 중복 요청을 합친다. 미완료 선점은 24시간 동안 다시 실행하지 않는다. 명시 재시도는 새 키를 쓰지만 동일 예산을 소비한다. 초안별 24시간 사업자 조회 5회·홈페이지 분석 3회, IP 시간 버킷별 합계 20회다. 제한되어도 직접 작성·저장·가입을 차단하지 않는다. Caddy가 X-Forwarded-For를 관리하고 앱 포트는 외부에 공개하지 않는 배포 전제를 유지한다.

## 배포와 롤백

1. 앱 재시작 전에 scripts/migrations/20261029-guest-quote-assist.sql을 적용한다. 재실행 가능하며 기존 게스트 초안 DDL이 선행되어야 한다. 조회·삭제·cron 경로가 새 테이블을 사용하므로 DDL을 생략하지 않는다.
2. 자동 입력·AI 보완·맞춤 산정은 별도 기능 플래그 없이 배포 즉시 제공한다. 기존 APICK_API_KEY와 NTS_SERVICE_KEY를 사용하며, 키가 없어도 확보 가능한 정보와 직접 작성·저장·가입으로 진행한다.
3. APICK_LLM_MODEL=deepseek-ai/DeepSeek-V4-Pro, APICK_LLM_THINKING=false가 기본이다. APICK가 thinking을 받는 전용 ID(deepseek-pro·deepseek-flash)에는 해당 옵션을 보내고, 카탈로그 ID에는 같은 설정을 speed=fast/slow로 변환한다. 기본 V4-Pro ID에 thinking을 직접 보내면 HTTP 400이므로 보내지 않는다. speed=fast는 빠른 추론 설정이며 전용 ID의 생각 모드 끄기와 동일한 내부 동작을 보장하지 않는다.
4. 정책의 등급 요율·부가세 조건과 동일 PG의 표준 요율을 점검한다. 금액이 없는 경우와 0% 등록 요율, 직접 작성·저장·가입도 확인한다.

공급자 장애는 기존 결과를 보존하는 fallback과 일시 호출 중단으로 처리한다. 환경변수 변경은 PM2 환경 갱신·재시작 후 반영한다. 코드 롤백 시 테이블은 즉시 삭제하지 않고 캐시 만료·청소를 유지한다. 사용자가 확인한 답변은 되돌리지 않는다.

## 관측과 검증

운영 Pino/Axiom의 guest_quote_analysis는 상태·AI 상태·제안 개수·반환된 호출 비용을 기록한다. guest_quote_completed는 서버 저장 후 초안 ID/revision·제안/수정/거절 개수·fallback 여부만 기록한다. 동일 초안의 재저장·재시도는 집계에서 초안별 최신 한 건으로 중복 제거한다. 수정 상태는 사용자 관측값이며 신뢰 경계가 아니다. 기존 funnel의 작성 완료·가입·최종 요청 성공과 연결해 fallback별 완주율을 비교한다. 회사명·번호·상품·홈페이지 원문을 새 운영 로그나 GA에 추가하지 않는다.

guest_quote_savings는 산정 가능 여부·사유와 계산된 PG·잠정 등급·제안 요율만 기록한다. 실제 견적과의 차이는 최신 산정 로그를 guest_rfp_drafts.id → completed_rfp_id → bids의 같은 PG 최신 회차로 연결하고, 해당 등급 카드 요율을 퍼센트·부가세 별도로 맞춰 비교한다. 로그 보존 범위 밖의 건이나 PG/등급이 다른 건은 비교에서 제외한다. 비용은 APICK 청구 내역과 대조한다. 응답 유실·프로세스 종료 건의 청구 여부는 로그만으로 확정하지 않는다.

검증 코드는 quote-assist 단위 테스트, quote-assist/quote-savings 서비스·route 테스트, quote-controller·GuestQuoteIntake·GuestQuoteSavings·가입 인계 테스트, DDL 재실행 테스트다. e2e/guest-quote-assist.spec.ts는 세 장애 응답을 HTTP 경계에서 재현하고 실제 초안 저장·가입 인계를 확인한다. 서비스 테스트가 공급자 호출/시간 초과/응답 검증을 별도로 검증한다. e2e/guest-savings.spec.ts는 실제 테스트 DB 정책·표준 요율과 서버 산정, 모바일·키보드·감소 모션·복원을 확인한다. 기능 플래그 없이 실행하며 Playwright 서버의 APICK_API_KEY는 비워 유료 호출을 차단한다. 실호출은 회귀 테스트와 분리해 아래 기록으로 남긴다.

### APICK 실호출 검증 (2026-10-29)

운영사에 공개된 사업자번호와 https://support-b.com 의 공개 내용만 사용했다. API 키·대표자명·APICK 원본은 기록하지 않았다. 회귀 테스트는 유료 API를 호출하지 않는다.

- 실제 `lookupQuoteBusiness`: APICK HTTP 200, api.success=true, 2,415ms, 50P. 회사명 제안과 별도 국세청 정상 영업·일반과세 확인이 함께 `complete`로 반환됐다.
- 실제 홈페이지 수집: 같은 호스트 공개 페이지 3개를 수집했다.
- 초기 LLM 요청은 카탈로그 V4-Pro에 `thinking=false`를 보내 HTTP 400·0P로 거절됐다. 진단 중 같은 오류를 총 3회 확인했다. 전용 ID만 thinking을 받고 나머지는 speed를 받도록 수정한 뒤 회귀 테스트를 통과했다.
- 수정한 기본 모델·`speed=fast` 요청: 실제 3개 페이지와 300자 공개 내용 표본 각각에서 8초 제한에 도달해 `failed`와 빈 AI 제안으로 반환됐다. 앞서 확보한 결과를 유지하는 경로다. 취소된 두 요청의 실제 청구 여부는 응답이 없어 확인하지 못했다.
- 별도 진단에서만 외부 요청 대기를 60초까지 허용했다. 같은 V4-Pro 요청이 12,841ms에 HTTP 200·api.success=true·5P로 완료됐다. 입력 420·출력 920 토큰 중 추론 860 토큰이 보고됐다. **제품의 제한은 여전히 8초다.** 이는 공급자 최종 응답 성공이며 제품 시간 내 AI 보완 성공으로 집계하지 않는다.
- 전용 `deepseek-pro`·thinking=false 조합도 공개 내용 300자 표본으로 실호출했다. 1,684ms에 HTTP 200·api.success=true·1P로 응답했지만 요구한 JSON 배열 형식 검증을 통과하지 않아 AI 제안을 폐기했다. API 성공과 유효 제안 성공은 구분한다.
