# 로그인 전 견적 작성과 이어쓰기

## 흐름

구매사 랜딩 → `/quote-start` → 홈페이지부터 기존 질문·첨부 작성 → 로그인/가입 → 이메일 인증·승인 → `/rfp-create?resume=guest` → 초안 선택 → 사업자 확인 → PG 추천 → 사용자의 최종 요청 순서다. 로그인된 구매사 CTA는 기존 `/rfp-create`를 연다. 공개 작성은 데모의 `guest` 모드가 아니다.

## 공개 작성 화면

`RfpQuestionFlow`의 `presentation="public"`은 `/quote-start`에서만 사용한다. 회원 작성·데모는 기본 표시와 기존 버튼 의미를 유지한다. 반응형 배치와 크기는 SCREEN_DESIGN.md의 공개 작성 확정 결정을 따른다. 완료·오류·계정 연결 안내도 같은 작업 영역을 사용한다.

- PC는 제목·설명과 질문 영역을 나란히 두고, 모바일은 같은 제목·설명 다음에 질문을 보여준다. 소개에는 `우리 사업에 맞는 PG 견적을 받아요`와 `사업 정보를 입력하면 업종에 맞는 PG사를 추천해요.`만 남긴다. 요청 순서·운영팀 전달·브라우저 보관 고지·추가 설명과 펼침 메뉴·안내 구분선은 제거하고 다른 위치로 옮기지 않는다(2026-10-14 사용자 결정). 모바일 이동 버튼은 하단에 고정하되 높이 500px 이하에서는 일반 흐름으로 돌아온다. 반응형 크기·배치는 SCREEN_DESIGN.md의 공개 작성 확정 결정을 따른다.
- 질문 정의가 홈페이지·판매 정보·계약 조건·마무리 영역과 선택 여부를 소유한다. 현재/전체 개수는 질문 위에 한 번만 표시하며 신규 14개·갱신 20개다. 유형에 따라 질문 수가 달라짐을 안내하고 갱신 선택 시 추가 질문 수를 접근성 상태 메시지로 알린다.
- 구축 방식·입점 판매자·배송 기간·선택 갱신 조건·추가 내용·첨부는 선택 Chip과 `지금은 건너뛰어요`를 제공한다. 건너뛰어도 입력·첨부를 지우지 않는다. 마지막 질문은 같은 전체 검증·저장 경로로 완료한다.
- 첫 질문은 `홈으로`, 마지막은 `작성 마치기`다. 완료 중에는 `저장 중…`과 실행 잠금을 적용한다. 1024px 미만의 이동·건너뛰기·인증 버튼은 최소 44px이며 다음 버튼이 더 넓고 건너뛰기는 별도 행이다. 모바일 버튼은 하단 고정, 높이 500px 이하의 창에서는 일반 흐름을 사용한다.
- 답변 저장 실패 시 오류·재시도를 제공한다. 첨부는 IndexedDB 원본을 별도로 확인하며 답변 저장 성공이 첨부 오류를 지우지 않는다.
- 공개 작성 화면의 일반 저장 상태 문구와 `초안 관리` 삭제 영역은 표시하지 않는다. 저장 실패 안내와 재시도는 유지한다(2026-10-14 사용자 결정).

### 입력과 완료 요약 (2026-10-15)

- 공개 작성의 텍스트·검색·숫자 입력은 6px 모서리와 얇은 테두리, 최소 44px 높이, 동일한 포커스·오류 표현을 쓴다. 질문과 중복되는 가시 라벨·완료 마커는 감추고 접근성 이름과 단위·도움말은 유지한다.
- 결제수단은 기존 브랜드 아이콘·카테고리와 이름, 우측 체크를 함께 표시한다. 선택 상태는 테두리·옅은 배경·체크로 구분하며 직접 입력의 추가·삭제도 최소 44px이다. 계약 유형은 같은 크기의 카드와 `PG와 처음 계약해요`·`기존 PG 계약을 갱신해요` 설명을 제공한다.
- 업종 카테고리는 이동 화살표, 실제 업종은 라디오를 사용한다. 검색창 아래 선택한 업종을 유지해 다른 카테고리·검색 결과를 탐색해도 확인할 수 있다. 검색·오타 처리·직접 입력 정책은 동일하다.
- 금액·기간의 숫자와 단위는 하나의 입력 묶음이다. 기간 단위는 일·주·개월이며 저장값은 기존 D/W/M+숫자를 유지한다. 연간 거래액 예시는 `1,000,000,000`이고 한글 금액 환산 안내를 제공한다.
- 첨부는 종류·이름·크기·제거 순서로 표시하고 제거 버튼의 접근성 이름에 파일명을 포함한다. 드래그 중 영역을 강조하고 실패 안내·재시도는 해당 파일 옆에 둔다. 복원한 메타데이터에 원본이 없으면 제거 후 재선택을 안내한다.
- 완료 화면은 결과 우선 슬라이더 계산기 → 로그인·가입 버튼 → 홈페이지·업종·계약 유형·갱신의 기존 PG 요약과 개별 수정 버튼 순서다. 계산기 기본값은 신규·갱신 모두 10억 원·1%p이며 가정임을 명시한다. 브라우저 보관 안내 문구는 표시하지 않는다. 슬라이더와 현재 값을 눌러 여는 직접 입력으로 연간·월평균 절감 예상액을 즉시 계산한다. 슬라이더 범위·직접 입력 확장·500ms 키보드 확정과 드래그 종료 확정 규칙은 SCREEN_DESIGN.md를 따른다. 계산기 값·최초 연출 여부는 `GuestQuoteStart`의 클라이언트 상태로만 유지하고 초안·회원 데이터·API·DB에는 저장하지 않는다. 답변 수정 후 복귀해도 값을 유지하고 최초 폭죽은 반복하지 않는다. 세부 계산·연출·접근성 규칙은 SCREEN_DESIGN.md의 공개 작성 완료 계산기 확정 결정과 DESIGN.md §9를 따른다. 로그인은 주 행동, 가입은 보조 행동이며 나머지 답변은 기존 `내용을 수정해요` 흐름으로 접근한다.
- 개별 수정은 별도 `RfpDraftProvider`의 임시 store에서만 진행한다. 취소는 원래 답변을 유지하고 요약으로 돌아간다. `수정 완료`는 현재 질문과 전체 필수 답변을 검증하며 신규→갱신으로 기존 PG와 연간 거래액이 필요해지면 임시 store에서 먼저 받는다. 검증 후 localStorage 저장이 성공한 뒤에만 실제 초안과 store를 갱신하고 요약으로 돌아간다. 실패하면 편집값·원본을 보존하고 재시도한다. 개별 수정은 작성 완료 운영 이벤트를 다시 보내지 않는다.

## 설계와 저장

- 작성 중에는 `support-b-guest-rfp-v1` localStorage와 `support-b-guest-rfp-files` IndexedDB를 사용한다. 기존 회원·데모 store는 격리한다.
- **가입 버튼**에서 `/api/guest-rfp/drafts`의 세션 → 답변 저장 → 파일별 presign/complete → 전체 완료 확인을 마친 뒤 가입 화면을 연다. 저장 중 중복 클릭을 막고 실패하면 입력을 유지한다. 재시도는 이미 ready인 파일을 건너뛰며, 문제 파일은 내용 수정에서 제거할 수 있다.
- `guest_rfp_drafts`는 버전드 공개 질문 답변, revision, 파일 manifest, 소유 사용자·워크스페이스·심사 신청, 요청 멱등 키, 완료·삭제 표식을 보관한다. `guest_rfp_files`는 원본 메타데이터와 pending/ready/deleting 상태를 소유한다. 계산기·PG 선택·마감 같은 내부 상태는 저장하지 않는다.
- 공개 접근 증명은 서버 발급 비밀값의 HttpOnly·SameSite=Strict·운영 Secure 쿠키다. DB에는 해시만 저장하며 UUID만으로 접근·연결할 수 없다. 쿠키가 사라진 미가입 초안은 복구할 수 없다.
- 첨부는 PDF/PNG/JPEG, 파일당 20MB·최대 5개다. 부모 행 잠금으로 개수와 가입 경합을 제어하고 기존 presigned 업로드 모듈의 크기·매직바이트·ETag 고정 승격을 사용한다. 원본은 R2의 기존 첨부 키 공간에 저장한다.
- 구매사 가입은 계정 생성·심사 신청·초안 연결을 같은 트랜잭션으로 처리한다. 연결 실패는 가입 전체를 되돌린다. 응답 유실/자동 로그인 실패는 로그인 복귀로 회복하며 연결된 미인증 계정은 재가입 정리에서 삭제하지 않는다.
- 인증·승인 대기 중에는 답변을 제공하지 않는다. 홈과 작성 페이지는 DB의 이메일 인증·활성 구매사·현재 사용자/워크스페이스를 확인한다. 승인 후 새 브라우저에서도 서버 초안을 찾는다.
- `/rfp-create?resume=guest`에서 서버/회원/다른 로컬 초안을 선택한다. 서버 초안을 선택하면 같은 파일 ID로 회원 첨부를 한 번만 만들고 재업로드하지 않는다. 같은 초안의 로컬 사본은 정리하고 기존 회원 초안은 그대로 남긴다. 자동 복귀는 최초 초안 선택에서 소비하며 이후 홈 링크로 접근한다.
- 복원은 사업자 확인 → 답변 재검증 → PG 추천 → 사용자의 최종 요청이다. 삭제된 업종 등 무효 질문으로만 되돌아간다. 수정은 서버 revision CAS로 저장하며 낡은 탭은 거부하고 실패는 재시도한다.
- 최종 요청의 소유권·revision·첨부를 재검증하고 견적 생성과 초안 완료를 같은 트랜잭션에 묶는다. 기존 요청 키/해시를 유지해 응답 유실 뒤 재전송을 합친다. 자동 요청은 없다.
- 기존 회원이 **로그인 버튼**으로 이어 쓰는 브라우저 전용 경로는 기존 로컬 복원·인증 업로드를 유지한다. 서버 저장·기기 간 복원은 가입 버튼으로 저장하고 가입에 연결한 초안에 적용된다.

### 보관과 정리 (2026-10-16)

미가입 서버 초안은 마지막 성공 저장 후 24시간이다. 가입 연결 시 만료를 제거하고 요청 완료·직접 삭제·계정 탈퇴까지 보관한다. 요청 완료 시 초안 답변은 비우고 완료 시각·요청 식별자를 남겨 재시도를 판정한다. 정식 견적의 첨부는 유지한다.

`/api/cron/sweep-uploads`는 만료된 미가입 초안과 1시간이 지난 pending 업로드를 한정된 배치로 정리한다. 삭제는 부모 잠금으로 가입·완료와 직렬화하며, 실제 업무에 연결된 첨부는 삭제하지 않는다. 원본 삭제 실패 시 `deleting` 행을 남겨 다음 cron에서 재시도한다. 삭제된 초안은 답변·파일 manifest를 비운 tombstone으로 남는다. R2의 기존 staging lifecycle도 유지한다.

브라우저 전용 사본은 종전 24시간 만료·탭 복귀/1분 주기 정리를 유지한다. 브라우저 중단 중에는 다음 실행 때 정리하며 원본 삭제 실패는 로컬 정리 기록으로 재시도한다. 서버에 연결된 사본은 브라우저 만료·데이터 삭제와 무관하게 복원할 수 있다.

### 입점 심사 알림

기존 ‘새 입점 심사 요청’ Slack에 **가입 커밋에 사용한 서버 답변**과 첨부 파일명·크기를 덧붙인다. 홈페이지·구축 방식·업종·상품·판매 정보·계약 유형·결제수단·갱신 조건·제목·메모를 포함하고 미입력과 아니요를 구분한다. 업종 이름과 선택지 라벨은 서버 공통 출처를 사용하며 자유 입력을 Slack escape한다. 첨부 원본·다운로드 URL은 보내지 않는다. 초안 없는 일반 가입·PG 가입은 기존 알림을 유지하며 Slack 실패는 가입 결과를 바꾸지 않는다. 기존 started/completed 이벤트의 좁은 요약과 별개다.

## 운영 이벤트와 공개 경계

공개 업종 목록은 `id/name/mccCode`만 SELECT한다. 기존 PG 입력에는 가입 화면과 같은 주요 PG의 ID·이름만 공개하며 전체 PG 디렉터리나 추천 정책은 공개하지 않는다. 추천 후보와 정책은 인증된 추천 단계에서만 조회한다. `/quote-start`는 정확일치 인증 예외이며 noindex/nofollow다.

`POST /api/guest-rfp/events`는 홈페이지에 공백이 아닌 첫 입력을 할 때 `started`, 전체 답변·원본 저장 후 인증 선택 화면으로 이동할 때 `completed`를 받는다. 두 이벤트는 초안 UUID로 연결한다. 서버 strict 스키마와 명시적 클라이언트 필드 구성이 홈페이지·업종·제목·계약 유형·첨부 개수와 선택 Clarity 사용자/세션 ID만 허용한다. 시작 이벤트에는 미완성 홈페이지를 보내지 않으며, 완료 이벤트는 유효한 홈페이지를 필수로 받는다. 단순 방문·포커스·저장 초안 복원은 시작으로 세지 않는다. 상세 방어와 한계는 [위협 모델 §7](THREAT_MODEL.md#7-로그인-전-견적-작성-2026-10-11)을 따른다.

Clarity에는 `guest_rfp_draft` 태그(초안 UUID)와 `guest_rfp_started`·`guest_rfp_completed` 이벤트를 남긴다. 현재 세션 metadata를 최대 1.5초 기다린 뒤 확보한 경우 Slack에 고정 프로젝트의 재생 링크를 붙인다. 차단·초기화 지연·오류 시에는 링크 미확보 안내와 함께 원래 알림을 보낸다. metadata 대기 중 페이지를 떠나면 `pagehide`에서 링크 없이 즉시 keepalive 요청을 시작한다. 늦게 도착한 metadata로 중복 알림을 만들지 않는다. Clarity 재생은 프로젝트 접근 권한과 녹화 수집·처리 여부에 달려 있으며, metadata 확보만으로 재생 가능성을 보장하지 않는다. metadata 콜백은 Microsoft 공개 SDK 소스에 있는 기능이지만 문서화된 안정 API 계약은 아니므로 공급자 변경 시 링크 없이 폴백할 수 있다.

`guest_rfp_events` 복합 PK로 전송 전에 선점한다. 결과는 `claimed`(미확정), `sent`, `failed`, `skipped`(웹훅 미설정)다. 실패를 사용자 업무에 전파하지 않으며 자동 재전송하지 않는다. 외부 Slack과 DB를 원자 커밋할 수 없으므로 중복 억제를 우선한 최대 한 번 시도이며, 정확히 한 번 도착을 보장하지 않는다. `guest_rfp.slack_failed`·`guest_rfp.event_failed` 로그를 확인한다. 요약 원문은 DB 이벤트 행에 보관하지 않는다.

## 배포·롤백

1. 앱 배포 **전에** 기존 `scripts/migrations/20261011-guest-rfp-events.sql`과 신규 `scripts/migrations/20261016-guest-rfp-drafts.sql`을 적용한다. 기존 테이블 데이터는 변경하지 않는다.
2. `guest_rfp_drafts`·`guest_rfp_files` 및 소유권/파일 상태 CHECK·부분 UNIQUE를 확인한다. `guest_rfp_events`의 `(draft_id,event)` PK와 event/result CHECK 제약을 확인한다. 기존 `SLACK_WEBHOOK_URL`을 사용하며 신규 환경변수는 없다.
3. 앱을 배포하고 공개 작성·로그인 복귀·두 이벤트 결과를 확인한다. 운영 smoke는 실제 Slack 알림을 만들므로 의도된 테스트 초안으로 실행한다.
4. 롤백 시 초안·파일·이벤트 테이블을 유지한다. 구 앱에서는 서버 초안 복원이 숨겨지므로 신규 코드 재배포로 복구한다. 원본을 지우는 테이블 DROP은 하지 않는다. 행을 지우면 이전 초안의 재시도가 중복 알림을 만들 수 있다. 사용자의 브라우저 저장 데이터는 서버 롤백으로 삭제하지 않는다.

이 작업에서는 격리된 테스트 DB에 스키마를 적용했으며 운영 DB 변경·배포·실제 Slack 발송은 수행하지 않았다.

실제 완료 화면과 슬라이더 조작 영상은 [계산기 미리보기](previews/guest-savings/README.md)에서 확인한다.

## 검증

단위/컴포넌트 테스트는 초안 격리·저장 오류·낡은 탭·계정/워크스페이스 고정, 첨부 부분 성공·원본 유실, 회원 초안 충돌, 인증 복귀, 공개 projection, 이벤트 중복·입력/Origin/크기·rate limit·Slack 실패를 확인한다. DB 테스트는 동시 claim과 명시적 공개 projection을 검사한다.
