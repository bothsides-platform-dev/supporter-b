# 업종 탐색 메타데이터

구매사와 관리자 모두 카테고리에서 쉬운 업종명과 예시를 찾는다. 검색은 현재 카테고리와 무관하게 전체 목록의 표시명·저장 이름·기존 표준 이름·예시·동의어·MCC 코드를 대상으로 한다. 목록과 검색 안내에는 MCC를 표시하지 않는다. 긴 목록은 페이지 스크롤을 사용한다.

구매사는 등록 업종만 단일 선택하고 기존 industryGroupId를 저장한다. 카테고리만 고르면 미완료이며 재진입 시 선택 업종의 카테고리를 연다. 빈 카테고리는 숨기고 직접 입력은 빈 목록·검색 결과 없음에서도 유지한다. 미등록 코드나 코드 없는 업종은 기존 이름으로 기타 업종에 둔다.

관리자의 표준 업종 등록은 카테고리를 넘어 복수 선택을 유지한다. 현재 목록 모두 선택은 보이는 미등록 항목만 추가하며 전체 선택 개수를 표시한다. 기존 코드·저장 이름을 기준으로 중복을 막고 서버 권한·중복 검증을 유지한다. 등록된 업종 관리에서는 필터 밖의 편집 폼을 hidden으로 숨겨 마운트와 미저장 값을 보존한다. MCC·판본은 분류 정보 펼침 영역에서 확인한다. 조회 전용 권한과 이름·접수 기준·추천 설정 폼은 유지한다.

## 동기화

원본은 구매사 저장소의 `lib/rfp/industry-display.json`, 관리자 사본은 `lib/industry-display.json`이다. 표시만 바꾸며 저장 이름·ID·정책·API·DB 스키마는 변경하지 않는다.

1. 원본의 version을 올리고 기존 29개 코드에 대한 category/displayName/examples/synonyms를 편집한다.
2. 같은 JSON 바이트를 관리자 저장소에 복사한다. MCC 원본 카탈로그는 수정하지 않는다.
3. 두 작업 브랜치에서 `rtk proxy cmp <구매사 작업 경로>/lib/rfp/industry-display.json <관리자 작업 경로>/lib/industry-display.json`으로 내용 일치를 확인한다.
4. 두 저장소의 탐색 테스트, 타입 검사, 린트를 실행한다. 코드 집합이 양쪽 MCC 카탈로그와 일치하는지 확인한다. 두 변경을 같은 릴리스에 반영한다.

현재 표시 메타데이터 판본: 1. MCC 분류 판본과 별도로 관리한다.
