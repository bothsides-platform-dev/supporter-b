# 가입 동의 증빙 — 문서 확정과 배포 순서

## 현재 상태

가입 동의의 서버 검증·트랜잭션 저장은 구현하지만, **승인된 고정 문서가 등록되기 전에는 출시할 수 없다.** `getSignupConsentDocuments()`의 현재 catalog는 `null`이다. 이 상태에서는 구매사·PG사 일반 가입, 워크스페이스 초대 가입, 기존 PG사 합류를 화면과 서버에서 모두 막는다. 이 변경을 문서 등록 없이 배포하면 신규 가입이 중단된다. 기존 계정의 로그인·기존 사용자의 초대 수락은 신규 가입 동의 수집 대상이 아니다.

이 문서는 운영 DDL 적용, 문서 공개·승인 또는 앱 배포를 실행했다는 기록이 아니다. 이 작업에서는 운영 DB와 배포를 변경하지 않았다.

| 개인정보 처리방침 | [Support B 개인정보 지침](https://moingclub.notion.site/Support-B-363ef44bd15380409aa1eabb4ab5b240) | 제1조~제15조. 현재 적용되는 시행일·판본 번호·이전 판본 링크가 표시되지 않는다. |

Notion 페이지 ID는 페이지의 위치를 식별할 뿐, 사용자가 본 본문의 판본을 고정하지 않는다. 조회일이나 배포 버전을 임의의 법률 문서 판본으로 사용하지 않는다. 현재 원문을 복사해서 공개하는 행위와 법률 문안의 확정도 이번 구현에서 수행하지 않았다.

출시 전에 문서 책임자와 운영 담당자가 다음을 확정해야 한다.

1. 이용약관·개인정보 처리방침의 최종 원문, 시행일, 판본 표기와 게시 승인을 확정한다. 필요한 법률 검토의 완료 여부도 담당자가 확인한다.
2. 선택 마케팅 고지의 최종 원문과 판본을 확정한다. 수신 채널·수신 목적·거부의 영향·철회 경로를 어떤 문구로 안내할지 승인한다. 체크박스 선택 사실의 저장만으로 이후 광고 발송 정책이 승인되는 것은 아니다.
3. 각 승인 문서를 덮어쓰지 않는 PDF 또는 정적 HTML로 공개한다. 권장 경로는 서비스가 소유한 도메인의 판본별 URL이다. 본문에 문서명·승인한 판본·시행일을 표시하고, 파일의 내용 해시와 승인 기록을 함께 보관한다. 새 판은 새 URL로 추가하며 과거 URL의 내용을 교체하지 않는다. Notion을 유지한다면 판본별 별도 페이지를 만들고 수정 권한·이전 판본 보존을 관리해야 한다.
4. 사용자가 로그인 없이 열 수 있는 고정 URL과 같은 판본을 catalog에 등록한다. 가입 화면의 링크·판본 표시와 서버의 허용 판본은 이 catalog를 공유한다. 테스트용 문서 fixture나 현재의 가변 Notion 주소를 승인된 고정본으로 등록하지 않는다.

내용 해시는 고정본의 동일성을 검사하기 위한 기술적 식별자다. 해시 생성은 법률 문안의 승인이나 시행일 확정을 대신하지 않는다.

## 저장 의미와 경계

`user_signup_consents`는 사용자 단위의 가입 시점 증빙이다. `user_id`를 기본 키로 사용하며, `terms_accepted`·`privacy_accepted`의 필수 동의, `marketing_accepted`의 선택 마케팅 동의 여부, 각 고지의 `*_version`·`*_url`과 서버 기록 시각 `recorded_at`을 보존한다. 필수 두 boolean은 DB에서도 `NOT NULL`과 `CHECK true`로 고정한다. 마케팅은 누락하면 `false`이며 필수 두 동의와 별도로 검증한다. 클라이언트가 보낸 시간 또는 sessionStorage의 기존 `agreedAt`은 서버 기록 시각의 근거가 아니다. URL·판본은 서버 catalog에서 선택한다. 본문과 해시를 증빙 행에 저장하지 않으므로 승인된 불변 원문을 별도로 보존해야 한다.

일반 가입은 `signupCompleteAction`의 buyer/pg 분기, 초대 가입은 `signupViaWorkspaceInviteAction`, 기존 PG사 합류는 `joinCanonicalPgWorkspaceAction`을 사용한다. 따라서 대상은 **네 경로와 세 액션**이다. 액션과 `AuthService`는 필수 동의 누락·허용하지 않은 판본·문서 미등록을 거부한다. 사용자를 만들고 워크스페이스를 생성하거나 합류하는 트랜잭션 안에서 동의 행도 작성하므로, 가입 트랜잭션이 실패하면 증빙만 남지 않는다.

가입 트랜잭션이 성공한 뒤 자동 로그인이나 이메일 발송이 실패한 경우에는 이미 생성된 계정과 증빙이 유지된다. 이를 가입 데이터의 롤백 대상으로 해석하지 않는다.

기존 사용자에게 동의 행을 생성하는 백필은 없다. 행이 없다는 뜻은 **동의 기록 없음**이며, 필수 동의 여부·마케팅 수신 여부를 추정하지 않는다. 행의 `marketing_accepted=false`는 새 가입에서 수신 동의를 하지 않았다는 기록으로, 행 부재와 다르다. 기존의 알림 설정·가입일·이메일 인증·워크스페이스 멤버십도 동의 증빙으로 바꾸지 않는다. 이후 마케팅 대상 조회는 기록 부재를 동의로 처리해서는 안 된다.

증빙의 수명은 사용자 계정의 수명에 따른다. 기존 회원 탈퇴의 soft-delete는 사용자 행을 남기므로 증빙도 남는다. FK는 `users(id) ON DELETE CASCADE`다. 미인증 계정을 정리한 뒤 같은 이메일로 다시 가입하는 경로는 이전 사용자 행을 물리 삭제하므로 이전 증빙도 삭제되고, 새 계정은 새 사용자 ID로 다시 동의한다. 이 정리와 새 가입은 같은 트랜잭션이므로 새 가입이 실패하면 이전 사용자와 증빙도 함께 복원된다. 이전 증빙을 새 계정으로 복사하지 않는다. 탈퇴 뒤의 별도 증빙 보관 기간이나 보존 주체는 이번 구현에서 임의로 정하지 않는다.

sessionStorage는 입력 복원만 소유한다. 현재 문서 판본과 일치하는 구조화된 동의만 복원하며, `agreedAt`만 있는 예전 초안이나 오래된 판본은 재동의가 필요하다. 마케팅 체크 상태도 독립적으로 저장·복원한다. 사용자가 첫 단계에 동의한 뒤 catalog가 변경되면 최종 제출에서 이전 판본을 거부한다. 재동의 복귀는 전체 페이지 이동(`window.location.assign`)으로 최신 번들과 문서 catalog를 다시 읽는다. 이전 탭의 캐시된 화면에 머물며 구 판본 제출을 반복하지 않는다. 필수 동의 누락·판본 불일치·문서 미등록은 draft를 유지한 채 역할에 맞는 `/signup/buyer?consent=review` 또는 `/signup/pg?consent=review`로 돌아가 재확인한다. 안전한 내부 `next` 목적지도 보존한다.

## 배포 순서

가입 첫 단계에서 이메일 중복 확인을 기다리는 동안에는 동의 체크를 잠근다. 화면의 선택과 제출된 선택이 달라지지 않게 하며, 문서 링크는 계속 열 수 있다. 제출 실패 후에는 체크를 다시 바꿀 수 있다.

1. 위 승인 항목과 문서 고정·공개를 끝내고 catalog를 등록한다. 배포 대상 코드에 등록된 문서가 `null`이면 중단한다. 구매사·PG사 가입 화면에서 고정 링크와 실제 본문 판본을 각각 확인한다.
2. 운영 변경 승인을 받은 배포 담당자가 `scripts/migrations/signup-consents.sql`의 additive DDL로 `user_signup_consents` 테이블을 **앱 배포보다 먼저** 생성한다. 기존 사용자 행은 갱신하지 않는다. 스키마 계획에 DROP 또는 기존 데이터 변환이 섞이면 별도로 검토하고 중단한다.
3. 선행 DDL의 테이블·사용자 FK·유일성·필수값 제약을 확인한 뒤 앱을 배포한다. 배포 스크립트는 이 테이블을 자동 생성하지 않는다. DDL 없이 앱이 먼저 배포되면 가입 INSERT가 실패한다.
4. 격리된 검증 환경에서 네 가입 경로의 동의 행, 서버 시각, 기본 마케팅 `false`, 잘못된 판본 거부와 가입 실패 시 롤백을 확인한다. 배포 뒤에는 승인된 테스트 계정으로 같은 경로를 확인하고 실제 사용자 데이터는 검사에 노출하지 않는다.

구체적인 운영 명령과 선행 DDL 경로는 [Lightsail 배포 런북](DEPLOY_LIGHTSAIL.md)의 가입 동의 절을 따른다. 워크트리에서 공유 로컬 DB를 대상으로 `pnpm db:push`를 실행하지 않는다.

## 복구와 남은 범위

문서 URL 또는 catalog 구성이 잘못되면 신규 가입을 중단한 채 승인된 고정본과 catalog를 복구한다. 필수 동의·판본 검증을 우회하거나 임시 판본을 만들어 가입을 열지 않는다. 동의 기록 기능이 없는 이전 앱으로 되돌리면 새 가입에 증빙이 다시 누락되므로, 롤백 중 신규 가입을 열어 두지 않는다. additive 테이블과 이미 저장된 증빙은 롤백 때 삭제하지 않는다.

가입 이후 동의 변경·철회, 약관 개정 재동의, 마케팅 발송 대상·수신거부 처리, 계정 삭제 후 보존 정책의 확대는 이번 변경 범위 밖이다. 이번 행은 가입 시점의 선택을 보존하며 현재의 마케팅 발송 가능 여부를 단독으로 나타내지 않는다.
