# 노온–구매사 장기부속합의 전환

## 현행 계약 흐름

배포 후 견적 선정 트랜잭션은 `kind=platform_buyer` 계약을 함께 만든다. 구매사는 딜룸에서 회사 정보 네 항목을 저장하고, 주식회사 노온이 날인한 PDF를 확인한 뒤 명시적으로 서명을 요청한다. 지정 담당자(견적 요청 작성자) 한 명이 SnowSign 이메일 링크에서 본인인증·전자서명한다. 노온 정보는 운영사 정보로 고정하고 PG는 이용 대상과 수수료 조건에만 표시한다.

약정기간은 실제 PG 서비스 이용 시작일부터 2년이다. 선정 PG 독점 이용과 할인액 반환 조건은 유지하며 반환 청구 주체는 노온이다. PG 정산대금 상계 조항은 없다. 개통일 입력·자동 만료 계산은 제공하지 않는다.

## 데이터와 신뢰 경계

- 기존 `signing_contracts`·`contract_archives`의 kind 기본값은 `pg_buyer`다. 기존 계약의 당사자·첨부·감사 기록을 변환하거나 삭제하지 않는다.
- 새 초안은 `platform_agreement_drafts`에 buyer 정보만 저장한다. 플랫폼 정보는 클라이언트 입력으로 받지 않는다. 레거시 `signing_agreement_drafts`·`sent_document`를 새 의미로 재해석하지 않는다.
- 새 `prepared`는 문안·buyer/platform·선정 견적·표준 요율 버전·서명 담당자·도장 버전/해시를 고정한 발송 스냅샷이다. 외부 계약을 만들기 전에 저장하며 providerRef가 생기면 수정할 수 없다. 미리보기·발송·보낸 합의서 조회가 같은 렌더러와 이 스냅샷을 쓴다.
- 도장 원본은 `lib/server/signing/assets/noon-seal-2026-10-21.png`에 보관한다. SHA-256은 `008201905d3942bd6228cc472b99ee3afa4cf84441c0d54a4dac0ee5533aadc8`이다. 원본은 .gitignore로 공개 저장소에서 제외하며 public이나 클라이언트 번들에 넣지 않는다. 공개 데모 PDF는 효력이 없는 합성 도장을 쓴다.
- 저장 revision CAS, PG 요율/계약 행 잠금, 미리보기 stamp, 발송 리스 및 providerRef CAS로 동시 변경·중복 발송을 막는다. 발송 응답 유실은 같은 providerRef를 조회해 구매사 단독 본인인증 정책을 확인한 뒤 복구한다. 조회가 실패하면 참조를 보존한다. 미발송 초안은 정리 후 새 미리보기를 요구한다.
- 구매사만 신규 계약 조회·저장·발송·PDF 다운로드를 할 수 있다. PG와 레거시 사용자 접근은 서비스/API에서 차단한다. 임베드·템플릿·복구 스캔·이어받기·수동 업로드 액션은 폐지됐다.
- 웹훅/폴링은 공급자 상태를 다시 읽고 신규 계약에 정확히 한 명의 지정 구매사와 `identity_verification`을 요구한다. 완료본과 감사추적인증서는 구매사 보관함에 한 번만 생성한다. 계약 알림은 구매사·운영자에게만 간다.
- 과거 발송 건은 내부 상태 동기화·보존만 유지한다. 과거 선정의 대기 계약 보정 생성과 사용자 재촉은 중단한다. 외부 SnowSign 계약의 일괄 취소는 하지 않는다.

## 배포 순서

1. 배포 커밋과 DB 대상을 확인하고 운영 `pg_dump`를 보관한다.
2. `scripts/migrations/20261021-platform-buyer-agreements.sql`을 `psql -X -v ON_ERROR_STOP=1`로 적용한다. kind 컬럼 두 개·CHECK·새 초안 테이블이 추가된다. 기존 대기 `signing.awaiting_template` outbox는 기록을 남긴 채 실패/재시도 소진 처리한다. 다른 메일은 건드리지 않는다.
3. kind 기본값/NOT NULL/CHECK, 새 테이블 PK/FK, 기존 계약·보관본 수와 참조 보존을 확인한다. 관리자 PG 표준 요율 테이블은 그대로 사용하므로 관리자 앱 변경은 필요 없다.
4. [Lightsail 런북](DEPLOY_LIGHTSAIL.md)에 따라 앱을 빌드·재시작한다. 원본 도장은 공개 Git에 넣지 않고 배포 전에 해당 서버 경로로 비공개 복사한다. 파일 권한은 앱 실행 계정만 읽도록 0600으로 설정하고 위 SHA-256을 확인한다. DB DDL 없이 앱부터 배포하지 않는다.
5. 배포 이후 테스트 견적을 선정해 구매사 작성·중단 후 복원·PDF 날인·PG 404/403을 확인한다. 승인된 테스트 담당자 한 명에게만 실제 서명을 요청하고 본인인증·서명 후 완료본/감사증명 수집을 확인한다.

구버전으로 되돌리면 PG 계약 기능을 다시 열고 신규 계약을 오해할 수 있다. 장애 시 신규 요청을 중단하고 전진 수정한다. 스냅샷·providerRef·kind·원본 파일은 삭제하지 않는다.

## 검증

`platform-agreement*.test.ts`, `platform-signing-policy.test.ts`, `platform-actions.test.ts`, `retired-signing.test.ts`가 계약 종류·원자 선정·권한·판본·응답 유실·동시 발송·웹훅 중복·보관함을 검증한다. `platform-agreement-migration.test.ts`는 DDL 재실행/기록 보존을 확인한다. `e2e/long-term-agreement.spec.ts`는 실제 로그인 구매사 작성·복원·PDF와 PG 경계를 확인하되 외부 발송은 하지 않는다. `e2e/buyer-demo.spec.ts`는 공개 데모가 업무 API를 부르지 않고 같은 순서를 체험하는지 확인한다.

단위 테스트는 합성 도장 fixture로 실제 PDF 렌더러를 검증한다. 실제 도장 브라우저 테스트는 비공개 원본이 없는 CI에서는 명시적으로 skip하며 원본이 설치된 로컬/서버에서 실행한다.

문서의 배포 절차는 실행 기록이 아니다. 실제 실행 결과는 릴리스 기록에 별도로 남긴다.
